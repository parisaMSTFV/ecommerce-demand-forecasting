# Data provenance

## Published case-study evidence

All customer demand records used by this project are generated by
`src/ecommerce_forecasting/data.py`.

The generator creates fictional product categories, calendar effects, planned
campaigns, discounts, availability constraints and random demand variation. It
does not reproduce, transform or sample any employer dataset. Category names,
volumes, elasticities, dates and event rules are illustrative.

Generated row-level data is written to `data/generated/` during execution and is
excluded from version control. The repository includes only aggregated,
reproducible evaluation tables and charts.

## User-supplied mode

`demand-forecast run-supplied` accepts aggregate category-day history and a
known-future driver plan under the versioned contract in
[`docs/supplied_input_contract.md`](docs/supplied_input_contract.md). The raw
CSV files are read from their original locations and are not copied to the
output directory.

Each run writes `input_provenance.json` with source-file SHA-256 hashes, row and
date coverage, and the submitted provenance declarations. Those declarations
are supplied by the user and are not independently verified. Derived report
tables can reveal business volumes, so users should write outputs only to an
approved location and must not commit confidential results to this repository.
